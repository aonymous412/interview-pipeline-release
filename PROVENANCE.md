# Provenance: how each published number is obtained

This file exists for the reader who wants to check the results rather than take
them, and for the one who finds the headline gap large enough to be suspicious.
It states where every number comes from, which links of the chain are verifiable
offline from this archive, and which are not.

## 1. What this archive is derived from

The code here is the evaluation harness as it ran, copied out of the research
repository. The repository stores code and its outputs side by side
(`results_ALI_v1.json` sits next to `run_phase2.py`); this archive regroups the
same files into `code/`, `data/`, `results/` and `reports/` so that they can be
navigated. That regrouping invalidates the path literals in the code, so import
statements and directory constants were rewritten to match.

**That is the only change.** No threshold, seed, formula, prompt, model name or
published value differs between the code here and the code that produced the
results. Every rewritten line carries a `[relocated]` marker, and `RELOCATION.txt`
lists the complete set — that file is generated by the build from the rewrites it
actually applied, so it cannot drift from the code beside it.

One data file was reformatted. `data/annotations/human_annotations_516.csv` was
written column-aligned, which padded the delimiters; a quoted evidence field
therefore began one space after its comma, and by RFC 4180 that quote is not a
quote character, so the commas inside those fields split the row. The file is
re-emitted as standard CSV. The build verifies cell by cell that the content is
unchanged, and then recomputes Cohen's $\kappa$ from the re-emitted file and fails
if it does not still equal the published 0.749 — so the reformatting cannot have
touched a label without stopping the build.

## 2. The chain, link by link

The claim under most scrutiny is ALI_v1 at 89.0% weighted coverage against 58.4%
for the strongest frontier baseline. It rests on four links.

**Link 1 — the parameter space and its weights.** `data/taxonomies.json` gives the
three domains: Consulting (17 parameters, $\sum w = 978$), Medical (17, 1010),
Payments (11, 535). These are curated, not learned, and they are fixed before any
run. They are the denominator of every coverage figure in the paper. Their weights
are a design choice and the paper argues for it; a reader who rejects the weighting
rejects the metric, and no amount of re-running changes that. This is the link
where disagreement is legitimate.

**Link 2 — from a transcript to a resolved frame.** The scorer decides, per
parameter, whether the transcript resolves it. This is the only link that depends
on a model, and it is therefore the weakest one. It is validated against 516 human
annotations at $\kappa = 0.749$ overall — but at **0.539 on Payments**, below the
0.65 threshold fixed in advance, and at **0.388** when restricted to the prompts
actually in the evaluation set. Both figures are published in the appendices of the paper
and neither is favourable. A reviewer weighing the headline gap should
weigh them: the metric's agreement with a human is good in Medical, mediocre in
Consulting, and poor in Payments.

**Link 3 — from a frame to a coverage number.** Arithmetic, and fully checkable
here. Each record stores `F_resolved`, the frame the run ended with.
`verify_numbers.py` recomputes $\mathrm{cov}(F) = \sum w_{\text{resolved}} / \sum w$
for all 450 ALI runs and compares it to the stored value: they agree exactly, to
the last bit, with no tolerance. It also checks that no frame key falls outside the
declared parameter space, that each domain's declared `total_weight` equals the sum
of its weights, that the per-turn trajectories are non-decreasing and end on the
final value, that every run labelled `coverage_reached` does reach its $\theta_d$,
and that every other run stopped at the 15-turn cap. Nothing in this link has to be
trusted.

**Link 4 — from coverage numbers to the published statistics.** Means, percentile
bootstrap intervals ($B = 10{,}000$, seed 42), turn counts, stopping rates, the
paired ablation and the $\theta$ sweep. All deterministic, all recomputed by
`verify_numbers.py` from the records and printed next to the value in the paper.

So links 3 and 4 are verifiable offline and exactly; link 1 is a stated design
choice; link 2 is the one that rests on a model, and its known weaknesses are
published rather than buried.

## 3. What this archive cannot prove

Running `verify_numbers.py` shows that the published statistics follow from the
stored records. It does not show that the records themselves came from honest runs
— no artefact can, short of re-execution. What is offered instead:

- **The transcripts ship.** Every ALI and baseline record carries its full
  conversation, so the scorer's verdicts can be read against the text that produced
  them, and disagreements can be found by hand rather than inferred.
- **Re-execution is possible** for anyone with API access (§ *Reproducing from
  scratch* in `README.md`), and will not reproduce a domain mean to the digit: the
  pipeline calls hosted models. Re-running an unchanged configuration two weeks
  apart moved a domain mean by 0.9 pp with 37 of 50 runs identical. That figure is
  in the paper so that differences of that size are not read as effects.
- **The evaluated harness is not the deployed architecture.** `code/ali/components/c3_generator.py`
  instantiates C3 with a single candidate question per turn; the reward-based
  ranking over six candidates described in the paper belongs to the production
  systems and does not run here. We ship the code that produced the numbers rather
  than the code that matches the architecture description. The README says so, and
  it is the first thing to check against the paper's Setup and Protocol subsection.
- **The baselines run under an eight-question instruction.** The interviewer prompt
  is in `code/phase1/run_multiturn.py`, quoted verbatim in the Reproducibility Artifacts
  appendix and discussed in the Baseline Interview Protocol appendix. It bounds the
  baselines, and the paper's 8-turn truncation control exists to measure what that bound
  is worth: ALI truncated to the same budget scores 84.4% rather than 89.0%, so the gap
  narrows but does not close. Read the two together, not the headline alone.

## 4. Where to start

```bash
pip install numpy
python verify_numbers.py
```

The integrity section runs before any comparison against the paper. If it passes,
the coverage values are arithmetic on the stored frames; the sections after it then
show the published statistics following from those values.
